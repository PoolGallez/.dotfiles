* Guide: what is in here and how to use it
This first part is documentation only: it contains no source blocks, so
nothing in it is tangled.  Everything from =* Pre-Early-Init= onwards is the
actual configuration.
** How the configuration is organised
This is a [[https://github.com/jamescherti/minimal-emacs.d][minimal-emacs.d]] based setup.  =Config.org= is the single source of
truth; saving it tangles (see "Auto-tangle on save") the generated files that
Emacs really loads:

| File               | Generated from section | Loaded                                  |
|--------------------+------------------------+-----------------------------------------|
| pre-early-init.el  | Pre-Early-Init         | before the UI is set up                 |
| post-early-init.el | Post-Early-Init        | after early-init, package archives      |
| post-init.el       | Post-Init              | after init: all packages, keys          |
| sprint.el          | (hand-written)         | by the "Sprint training system" section |

Never edit the generated =.el= files by hand: they are overwritten on the
next save of =Config.org=.  The directory lives in the dotfiles repo
(=~/.dotfiles/emacs/.config/emacs=) and is symlinked into =~/.config/emacs=
with GNU Stow, so the same config runs on Linux (NixOS), Windows and Android.
Open it from anywhere with =SPC c=.

*Control Panel* (Post-Init) is the only place to touch when setting up a new
machine: the platform is auto-detected, and per-platform feature flags
(=glz/enable-org-roam=, =glz/enable-magit=, =glz/enable-sprint=, ...) decide
what gets loaded.  Paths are derived from =glz/org-directory= (=~/PKDB/=).

** The PKDB knowledge base
PKDB ("personal knowledge database") is a plain folder, =~/PKDB=, identical
on every device.  Emacs creates missing folders and the six core org files
at startup, and never touches existing ones.

| Path          | Purpose                                                          |
|---------------+------------------------------------------------------------------|
| Tasks.org     | all tasks (agenda)                                               |
| Calendar.org  | appointments (agenda)                                            |
| Birthdays.org | birthdays (agenda)                                               |
| Archive.org   | refile target for finished or cancelled items                    |
| Health.org    | body measurements: the Weight table (weekly weigh-in)            |
| Keep.org      | quick notes and checklists, Google Keep style (agenda, =SPC n=)  |
| Notes/        | long structured notes, one folder per course, chapters in files  |
| roam/         | org-roam Zettelkasten (small linked notes, daily notes)          |
| Athletics/    | TrainingDB.org (exercise database) and Sprint/ (training system) |
| Resources/    | lecture PDFs, books, labs: synced, never versioned in git        |

*** Tasks and agenda
Capture is the entry point: everything goes into =Tasks.org= and is
organised afterwards.
- =SPC o c= opens the capture menu: =t= task, =d= task with deadline, =b= birthday,
  =w= weight (kg and an optional note, appended as a dated row to the Weight
  table of =Health.org=; checked to be 30–250 kg, a comma decimal is fine).
  Storing a weight completes the repeating "Weigh in" task of =Tasks.org=
  (property =:WEIGH_IN: t=), so the weekly reminder moves on by itself.  The
  sprint report reads the table for the weight trend and strength per kg.
- A task records where it was captured (=:ORIGIN:= link to the buffer you
  were in) and gets project tags, defaulting to the =project.el= project of
  that buffer, so tasks captured from a repo are filtered by that repo.
- Keywords: =TODO IN-WORK DONE= for plain tasks (=IN-WORK= clocks in, see
  Automatic clocking), and =IDEA DISCUSSION ANALYSIS DONE CANCELLED= for work
  items, which go =IN-WORK= too once someone works on them.  The training
  schedule has its own set, =TODO IN-WORK DONE SKIPPED=.  Closing a task logs
  the time into the =LOGBOOK= drawer.
- =SPC o a= opens the agenda.  The custom view =d= (Dashboard) shows the week
  with deadlines in the next 7 days, the tasks =IN-WORK= and the active
  projects; =n= lists only the =IN-WORK= ones; =e= lists low-effort open
  tasks (under 15 min); =SPC o m= lists the open tasks of one project tag.
- Finished items are moved with refile (=SPC o w=) to =Archive.org=, or
  archived (=SPC o A=).  Time can be tracked with the clock map =SPC o C=.
*** Notes and org-roam
Course notes live in =Notes/<course>/= as an index plus chapter files.
=org-roam= (=SPC o r=) handles the Zettelkasten in =roam/=: find or create a
node, insert a link to a node, toggle the backlinks buffer, daily notes, and
a graph view in the browser (desktop only).  On a phone, =SPC o r= opens the
roam folder in Dired when SQLite is unavailable.  Images are pasted or
dropped into notes with org-download, and equations are previewed with
AUCTeX's preview-latex (see the LaTeX preview section).

** Sprint training system
A small training-planning engine for a 100 m sprinter, written in
=sprint.el= and driven by plain org files in =~/PKDB/Athletics/Sprint/=.
The idea: *one config file is the single source of truth*; the plan, the
day-by-day schedule and the readiness rules are all derived from it.

| File                     | Role                                                                                                                                    | Who writes it |
|--------------------------+-----------------------------------------------------------------------------------------------------------------------------------------+---------------|
| sprint_config_YYYY.org   | every tunable parameter, as #+MACRO lines (season start, competition dates, phase lengths, readiness thresholds, previous-season bests) | you, by hand  |
| sprint_plan_YYYY.org     | the plan template; reads the config through #+SETUPFILE, weekly tables per phase                                                        | you (rarely)  |
| sprint_schedule_YYYY.org | the generated calendar: weeks, days, sessions                                                                                           | SPC o S g     |
| sprint_log_YYYY.org      | what actually happened: sessions (exercise by exercise), tests, races                                                                   | SPC o S L, org-capture |
| sprint_adjust_YYYY.org   | proposals of the weekly review and manual overrides, with their fate (the tuning history)                                               | SPC o S W / o, you |
| ../TrainingDB.org        | exercise database: categories, CNS, F-V bias, rule flags, harder variant (PROGRESSION)                                                  | you           |
| GAPS.org                 | open issues and design notes of the system                                                                                              | you           |

The season is split into 8 phases (Fundamental I, Fundamental II, indoor
competition, Transition I, Transformation, outdoor competition,
championship peak, Transition II); the indoor phases are skipped when
=INDOOR_SEASON= is =false=.  Weeks are typed LOAD, DELOAD, COMP or TRANSITION; the
testing battery is scheduled in every deload week.  The current season is the
highest =sprint_config_YYYY.org= found.

*** Workflow
1. *Set up the season.*  Edit =sprint_config_YYYY.org= (season start must be a
   Monday, competition dates, targets).  Run =SPC o S v= and fix what the
   validator reports, then =SPC o S g= to generate the schedule.
2. *Every day.*  =SPC o S i= tells you the phase and the planned session;
   =SPC o S a= shows the sprint agenda.  After training, =SPC o S L= logs the
   session exercise by exercise (times, kg×reps, done/modified/skipped), then
   CMJ height, session RPE, soreness and duration, and marks the schedule entry
   =DONE= or =SKIPPED=.  =SPC o S s= is the quick session-level capture.
   Weekly: =SPC o S R= report, =W= review (proposals), =A= apply.
3. *Readiness is computed on save of the capture.*  The CMJ is compared to
   the baseline (percentage, =CMJ_PCT=), combined with the previous session's
   RPE and the soreness into Green / Yellow / Red with advice (Yellow: drop
   very high CNS work and cut plyometric contacts by 30%; Red: low-CNS day
   only).  If the CMJ is below the overreach limit for three sessions in a
   row, the entry is flagged =OVERREACH= and an unplanned deload week is advised.
4. *Tests and races.*  =SPC o S t= (or =SPC o S L= on a testing day) and
   =SPC o S r= store results under the =Testing Battery= and =Races= headings
   of the log; implausible test values are refused, since the tests set the
   target times.  A race with wind above
   2.0 m/s is automatically marked =LEGAL: no= and ignored for personal bests.
5. *Regenerating.*  Running =SPC o S g= again after changing the config keeps
   all weeks before the current one, locked weeks and hand-edited weeks
   untouched and rebuilds the current week onwards; sessions already =DONE= /
   =SKIPPED= in the current week stay as they are.  An open schedule buffer is
   saved first and reverted afterwards.  Narrower changes: =SPC o S o=
   (override weeks), =w= (swap an exercise), =x= / =X= (redraw).
6. *End of season.*  =SPC o S y= shows the season's bests (10 m and 30 m
   times, 100 m PB, CMJ baseline, estimated 1RM from 3RM with Brzycki).
   =SPC o S n= then creates the next season's files: dates move forward 52
   weeks and are flagged for review, and the =PREV_*= values come from the
   log.  Replace the competition dates with the real calendar, validate and
   generate.
*** Generated exercises and weekly load
=SPC o S g= does not only lay out the calendar: it fills every session with a
starting-point list of exercises, so you adjust instead of writing from scratch.
- *Categories.* The session text of the weekly templates ("Acceleration +
  Technical Drills + Strength (Max Force)") is matched against the 20 DB
  categories (=sprint--category-keywords=).  Warm-Up is added on High days.
- *Selection.* For each category, exercises are sampled from =TrainingDB.org=,
  at most =sprint-exercises-per-category= per session, skipping exercises whose
  CNS demand is too high for a Low day and any =sprint-unavailable-equipment=.
  An exercise named in the template ("Power Clean") is used as is.
- *Variation.* Least-used exercises first, then the least recently used, a
  different SUBCATEGORY inside the same slot, never the same exercise twice in
  a week, and no drawn exercise more than =ROTATION_WEEKS= weeks in a row.
  Late in a block an exercise gives way to its harder variant (=PROGRESSION=,
  marked ↑).  The whole season is simulated in order, so reruns give the same
  result.
- *Load.* Lifts with config entries (squat, trap bar DL, power clean, Nordic)
  get sets × reps @ % and kg (from =PREV_*_1RM=).  =LOAD_START= → =LOAD_END=
  is interpolated over the loading weeks of the sub-phase (or phase); a
  deload week halves the sets.  Volume targets (acceleration m, max-velocity m,
  speed-endurance m, plyo contacts) are listed per session, halved on deload.
- *Editing.* Edit the generated lines freely: a week whose exercise lines
  differ from what was generated (=:GEN_HASH:=) gets =:LOCKED: yes= on the next
  regeneration and is kept; =SPC o S l= toggles the lock (=no= rebuilds it).
  =SPC o S w= swaps one exercise, =x= / =X= redraw a session / week.
- *Separate venues.* With =SPLIT_VENUES yes= no session mixes track and gym:
  the strength of the plan's sprint days moves to the gym days of the weekday
  pattern (=Gym: …= sessions, tagged =:gym:=), and equipment-bound exercises
  only go where the equipment is.
- *Rules.* The spacing and injury rules (48 h between max-velocity days, ...)
  and the F-V emphasis steer the selection; what cannot be avoided is listed as
  WARNING lines at the top of the schedule.  Volume targets are constant inside
  a sub-phase unless an override scales them.
- Full user guide: =~/PKDB/Athletics/Sprint/README.org=.
*** Using it from the phone
=glz/enable-sprint= is on for Android too: the same captures work on the
phone, so you can log a session right after training.  Syncthing then
propagates the log to the other devices (see "Syncing PKDB").

On the phone everything starts from the *dashboard* (the first buffer, or the
home button of the tool bar): tap /Today's training/ to see the session with
its exercises as TODOs, /Log the session/ for the exercise-by-exercise form,
/Not as planned/ when the day went differently, and /All sprint commands/ for
the rest of the =SPC o S= map as a tappable list.  The ✓ / ✗ buttons of the
tool bar finish or abort the capture or log form (=C-c C-c= / =C-c C-k=).
Each of these (and new note, notes board, ...) can also get its own icon on
the home screen: see "Shortcuts from outside Emacs".
** Git, projects and the rest
- *Magit* (=SPC g g=) is the git client; =project.el= is advised so every
  project gets its own *perspective* (workspace with its own buffers),
  switched with =SPC w p=.  Forge adds GitHub/GitLab on Linux.
- *Conflicts*: =SPC g e= for ediff and =SPC g m= for smerge, inline.
- *Completion*: Vertico, Orderless, Marginalia, Embark, Consult for the
  minibuffer; Corfu in buffers; eglot + clangd for C/C++.
- *Platform-specific modes*: Testfall, Anforderungen and CANAPE PAR (work
  tooling, Windows only), Nix mode (Linux).
- *Android*: one bottom tool bar (dashboard, capture, training, agenda,
  back, save, undo, finish/abort, M-x), full-screen buffers, touch selection
  and scrolling, larger font (see Post-Init → Android touch ergonomics), and
  Termux binaries on the =PATH= (needs the shared-UID setup described in
  Pre-Early-Init).

** GC threshold after startup
minimal-emacs sets gc-cons-threshold to most-positive-fixnum during startup and
restores it afterwards. Override the restore target to 2 MB (matching a typical
Emacs tuning recommendation) instead of the default 32 MB.
#+begin_src emacs-lisp
(setq minimal-emacs-gc-cons-threshold (* 2 1000 1000))
#+end_src
** Touch-friendly UI on Android
minimal-emacs.d disables the menu bar, tool bar, and context menu everywhere
by default (they cost a startup redraw and desktop workflows here are
keyboard-driven).  On a touchscreen those are exactly the affordances that
make commands discoverable without memorizing keybindings, so re-enable
them for Android only.  This must run in pre-early-init.el: it sets
=minimal-emacs-ui-features= before early-init.el reads it, and =glz/platform=
(defined later, in post-init.el) doesn't exist yet at this point in startup.

The tool bar goes to the *bottom* of the frame, where the thumb is (the same
choice most Emacs-on-Android setups make).  Putting it in
=default-frame-alist= here, before the first frame exists, avoids a
redraw that =customize-set-variable= would cost later.  Its buttons are
defined in Post-Init → Android touch ergonomics.
#+begin_src emacs-lisp
(when (eq system-type 'android)
  (setq minimal-emacs-ui-features '(menu-bar tool-bar context-menu dialogs))
  (setq tool-bar-position 'bottom)
  (push '(tool-bar-position . bottom) default-frame-alist))
#+end_src
** Termux binaries on PATH
Lets Emacs shell out to whatever's installed in Termux (git, ripgrep,
python, ...) from eshell/vterm/compile/etc — Emacs itself can't install
arbitrary command-line tools on Android, so this is the way to get them.

Android sandboxes every app's data directory from every other app by
default, so =/data/data/com.termux/files/usr/bin= is normally invisible to
Emacs even though it exists on the device. Seeing it requires Emacs and
Termux to be installed with a shared Android =sharedUserId= — a one-time
step done outside Emacs entirely (re-signing both APKs with the same
certificate so Android treats them as the same "user"); see
https://marek-g.github.io/posts/tips_and_tricks/emacs_on_android/ for the
full apktool/apksigner walkthrough. Without that step this block is a
harmless no-op (the path just isn't there to add), so it's safe to carry
even before you've decided whether to do the APK surgery.

Also works around the F-Droid build of Emacs for Android, which ships
without built-in gnutls — without a TLS backend, package.el and anything
else needing HTTPS fails outright. Probing =gnutls-available-p= (same
capability-check approach as the sqlite check for Org Roam) instead of
assuming means this only kicks in on the builds that actually need it;
the external =gnutls-cli= it shells out to must itself come from Termux,
so it only helps once the PATH above is wired up.
#+begin_src emacs-lisp
(when (eq system-type 'android)
  ;; No file-directory-p guard: it returned nil this early on the phone even
  ;; though the directory is usable, which silently skipped the PATH setup.
  (let ((termux-bin "/data/data/com.termux/files/usr/bin"))
    (setenv "PATH" (concat termux-bin ":" (getenv "PATH")))
    (push termux-bin exec-path))

  (unless (gnutls-available-p)
    (setq tls-program '("gnutls-cli -p %p %h"
                         "gnutls-cli -p %p %h --protocols ssl3"))))
#+end_src

| Module          | Enabled on                                       |
|-----------------+--------------------------------------------------|

| org-roam-ui     | linux                                            |

| nix-mode        | linux                                            |
| testfall        | windows                                          |

Android gets no clangd LSP, PDF, or LaTeX-preview native-compile
dependencies, and no OS-shell-out for external files — none of those have a
realistic path to working on a phone. The git-workflow tooling
(magit/ediff/smerge) is the one exception: it's off by default, same as
before, but turns itself on if the Termux =git= binary is actually reachable
(see Pre-Early-Init → Termux binaries on PATH) — probed with
=executable-find=, not assumed, since it depends on the Termux
=sharedUserId= setup having actually been done.

Org Roam is the one exception worth enabling on a phone — reading notes is
the main Android use case — but its database needs SQLite, and the only
fallback for a build without one compiled in is a native module that needs
a C compiler at runtime, which a packaged Android app won't have. So probe
for it instead of assuming: enable Org Roam on Android only when
=(sqlite-available-p)= is true. When it isn't, =SPC o r= still gets you to
your notes — it just opens the roam directory in Dired instead of the
fuzzy node finder (see the Org Roam section). org-roam-ui (the graph
viewer, served over a local webserver you'd open in a browser) stays
desktop-only regardless, sqlite or not — not a touch workflow.

See the packages below for what Android gets instead (touch-friendly
menu/tool bar, corfu completion, org, dired, org-capture, etc. all stay on
for every platform).

#+begin_src emacs-lisp
(defvar glz/enable-org-roam
  (or (memq glz/platform '(linux))
      (and (eq glz/platform 'android)
           (fboundp 'sqlite-available-p)
           (sqlite-available-p)))
  "Org Roam's database wants Emacs's built-in SQLite. On Android the
alternative is a native module that needs a C compiler at runtime, which
isn't available, so this probes for the built-in support instead of
assuming the platform has it.")
(defvar glz/enable-org-roam-ui     (memq glz/platform '(linux)))
(defvar glz/enable-forge           (memq glz/platform '(linux)))
(defvar glz/enable-nix             (memq glz/platform '(linux)))
(defvar glz/enable-testfall        (memq glz/platform '(windows)))
(defvar glz/enable-anforderungen   (memq glz/platform '(windows)))
(defvar glz/enable-canape-par      (memq glz/platform '(windows)))
(defvar glz/enable-lsp-c           (memq glz/platform '(windows linux)))
(defvar glz/enable-latex-preview   (memq glz/platform '(windows linux)))
(defvar glz/enable-open-externally (memq glz/platform '(windows linux)))
(defvar glz/enable-magit
  (or (memq glz/platform '(windows linux))
      (and (eq glz/platform 'android) (executable-find "git")))
  "Needs the real git binary, which on Android only exists via the Termux
PATH bridge (see Pre-Early-Init) once the shared-UID setup is done. Probes
for it instead of assuming, same pattern as the Org Roam sqlite check.")
(defvar glz/enable-pdf-tools       (memq glz/platform '(windows linux)))
(defvar glz/enable-sprint          (memq glz/platform '(linux android)))
#+end_src

*** Android touch ergonomics
The phone setup follows what most Emacs-on-Android configurations converge
on: one keyboard that has the modifiers, one thumb-reachable tool bar with
the few commands a phone session needs, and every buffer taking the whole
screen instead of splitting a portrait display in two.

*Modifiers come from the keyboard.*  Unexpected Keyboard already has
Ctrl/Alt/Esc/Tab keys, so Emacs's own =modifier-bar-mode= (a second tool bar
with the same buttons) is not used: it would only take screen space twice.
For a Bluetooth/USB keyboard, /External Keyboard Helper/ fixes up modifier
keys Android otherwise mishandles.

*One tool bar, at the bottom* (placed there in Pre-Early-Init).  The default
desktop tool bar (new file, open, cut, copy, paste, ...) is replaced by:

| Icon       | Action                                                          |
|------------+-----------------------------------------------------------------|
| home       | dashboard                                                       |
| keyboard   | show the on-screen keyboard (also =SPC t k=); the icon is drawn |
|            | in the config, since Emacs has none                             |
| new        | org-capture                                                     |
| unchecked  | TODO state / clock in-out of the entry at point, as a popup     |
|            | (Org buffers and agenda; see Automatic clocking)                |
| left-arrow | back: leave the minibuffer, close a split, or previous buffer   |
| open       | open or create a file                                           |
| diropen    | open a folder (Dired)                                           |
| close      | close this buffer                                               |
| save, undo | save buffer, undo                                               |
| cut, copy  | cut / copy the selection (greyed out without one)               |
| paste      | paste                                                           |
| search     | isearch                                                         |
| checked    | finish: what =C-c C-c= does here (capture, log form, ...)       |
| cancel     | abort: what =C-c C-k= does here                                 |

These are the usual Emacs buttons plus the phone ones; on a narrow screen
the bar wraps onto a second row.  The keyboard sits next to home, so it is
always on the first row.

The finish/abort buttons are greyed out where those keys do nothing.  The
built-in tool bar is never built at all (=tool-bar-setup= is skipped), which
also saves a little startup time.  The Android *Back* key does the same as
the back button.

*Full-screen buffers.*  On a desktop, help, reports and forms pop up next to
the buffer you are in; on a phone that halves an already small screen.  On
Android every buffer is shown in the selected window instead, except small
helpers (completion list, capture/agenda menus, calendar, which-key,
transient, warnings), which stay temporary splits.  Org manages a few windows
itself, outside =display-buffer-alist=, so they are set separately: the
agenda and source-block editing reuse the current window, and the capture
buffer takes the whole frame (the previous layout comes back when the
capture is finished).  =q= / back returns to the previous buffer.

*Touch.*  =touch-screen-precision-scroll= and =pixel-scroll-precision-mode=
make dragging track the finger instead of jumping by lines; a long press
selects a word, which can then be extended by dragging
(=touch-screen-word-select=, =touch-screen-extend-selection=), with a preview
of the text under the finger.  Minibuffer candidates (Vertico) can be tapped
(=vertico-mouse-mode=).  The mode line drops the encoding and minor modes and
shows only the buffer name, so the information that matters fits a portrait
screen.  The default face is bumped up ~15% (fine-tune with =SPC t ==, then
=+=/=-=/=0=).

*** Unicode fallbacks (fonts that lack a symbol)
The config shows a few non-ASCII symbols: arrows in the menu labels, bullets,
=·=, =…=, =✓=, =×= in the sprint reports, and so on.  A font without one of
them (the phone's, and sometimes Windows') draws boxes or random symbols.

When the first graphical frame exists, every symbol of
=glz/unicode-fallbacks= that no installed font can display is replaced
everywhere by its ASCII stand-in (=→= becomes =->=), using Emacs's own
=glyphless-char-display= table, so no label has to change.  The org heading
bullets, list bullets and fold marker are drawn differently (compositions
and the ellipsis), so they are chosen with =glz/glyph= instead, again at the
first graphical frame: a desktop daemon starts without one.
#+begin_src emacs-lisp
(defconst glz/unicode-fallbacks
  '((?→ . "->") (?← . "<-") (?↑ . "^") (?↓ . "v") (?▲ . "^") (?▾ . "v")
    (?· . ".") (?… . "...") (?• . "*") (?« . "<<") (?» . ">>")
    (?— . "-") (?– . "-") (?− . "-") (?─ . "-") (?━ . "=")
    (?× . "x") (?≈ . "~") (?≥ . ">=") (?✓ . "+") (?✗ . "x") (?📌 . "*")
    (?◉ . "*") (?○ . "o") (?● . "*"))
  "Non-ASCII symbols the config shows, with ASCII stand-ins for fonts that lack them.")

(defun glz/glyph (preferred fallback)
  "PREFERRED if a font can display it, else FALLBACK.
Before any graphical frame exists (a daemon starting up), PREFERRED."
  (if (or (not (display-graphic-p))
          (seq-every-p #'char-displayable-p preferred))
      preferred
    fallback))

(defvar glz/unicode-check-hook nil
  "Run once a graphical frame exists, to choose symbols with `glz/glyph'.")

(defvar glz/unicode-checked nil "Non-nil once `glz/unicode-check' ran on a graphical frame.")

(defun glz/unicode-check (&rest _)
  "Replace the symbols no font can display, once, on the first graphical frame."
  (when (and (not glz/unicode-checked) (display-graphic-p))
    (setq glz/unicode-checked t)
    (pcase-dolist (`(,char . ,ascii) glz/unicode-fallbacks)
      (unless (char-displayable-p char)
        (set-char-table-range glyphless-char-display char ascii)))
    (run-hooks 'glz/unicode-check-hook)))

(add-hook 'emacs-startup-hook #'glz/unicode-check)
(add-hook 'server-after-make-frame-hook #'glz/unicode-check)

*** Auto-save cleanup
init.el already redirects every auto-save file into a single
=user-emacs-directory/autosave/= folder (hashed names, one per visited
file) instead of scattering =#file#= next to the real files — that part
already works. What it doesn't do is prune it: a buffer only loses its
auto-save file on an explicit kill (=kill-buffer-delete-auto-save-files=),
so one that's never closed (the daemon runs for days) or a crash leaves
it there forever. Mirrors the =recentf-cleanup= pattern above and the
=nix.gc= "=--delete-older-than 15d=" convention already used for the Nix
store in the nixos config — same age threshold, same idea, different
store.
#+begin_src emacs-lisp
(defun glz/cleanup-stale-auto-saves ()
  "Delete auto-save files older than 14 days from `auto-save-list-file-prefix'."
  (let* ((dir (file-name-directory auto-save-list-file-prefix))
         (cutoff (- (float-time) (* 14 24 60 60))))
    (when (file-directory-p dir)
      (dolist (file (directory-files dir t "\\`[^.]"))
        (when (and (file-regular-p file)
                   (< (float-time (file-attribute-modification-time
                                    (file-attributes file)))
                      cutoff))
          (delete-file file))))))

(run-with-idle-timer 30 nil #'glz/cleanup-stale-auto-saves)
#+end_src

**** Automatic clocking and the TODO-state menu
Time is tracked by changing states, so the clock commands (=SPC o C=) are
rarely needed by hand:

- *Entering =IN-WORK= clocks in* (clocking in on another entry clocks the
  previous one out, as Org always does).
- *Leaving =IN-WORK= clocks out*, whatever the new state: DONE, CANCELLED,
  SKIPPED, or back to TODO.

So in a training session (=SPC o S t=) you set an exercise =IN-WORK= when you
start it and DONE when you finish it, in whatever order the gym allows; each
one gets its own =CLOCK:= line, and the log form copies the minutes into the
training log.  It works however the state is changed (=C-c C-t=, =SPC o t=,
shift arrows, the agenda, the menu below).  =org-clock= is loaded on the
first state change: Org only loads it on the first manual clock-in, and
without it a fresh Emacs changed the state but never clocked.

=glz/org-todo-menu= shows the TODO states of the entry at point (the file's
own =#+SEQ_TODO= ones, e.g. SKIPPED in the sprint schedule) plus /Clock in/
and /Clock out/ as a popup menu, in Org buffers and in the agenda.  It is
the tool bar button on Android (=unchecked= icon, next to capture): a tap
on the button, a tap on the state.
#+begin_src emacs-lisp
(defvar glz/org-clock-in-states '("IN-WORK")
  "TODO states that clock the entry in when it enters them.")

(defun glz/org-clocking-here-p ()
  "Non-nil when the running clock is in the entry at point (its CLOCK line).
Indirect buffers (e.g. the sprint \"today\" view) count as their base buffer."
  ;; `org-clocking-p' is not autoloaded: org-clock.el is only loaded by the
  ;; first manual clock-in, so a fresh Emacs would fail here without this.
  (require 'org-clock)
  (let ((base (lambda (b) (or (buffer-base-buffer b) b))))
    (and (org-clocking-p)
         (eq (funcall base (marker-buffer org-clock-marker)) (funcall base (current-buffer)))
         (save-excursion
           (org-back-to-heading t)
           (and (<= (point) org-clock-marker)
                (> (org-with-wide-buffer (org-entry-end-position)) org-clock-marker))))))

(defun glz/org-auto-clock ()
  "Clock in on entering `glz/org-clock-in-states', out on leaving them.
Runs from `org-after-todo-state-change-hook' (point on the changed entry).
Org clocks a DONE entry out by itself; this also covers going back to TODO."
  (save-excursion
    (org-back-to-heading t)
    (let ((here (glz/org-clocking-here-p)))
      (cond ((member org-state glz/org-clock-in-states)
             (unless here (org-clock-in)))
            (here (org-clock-out nil t))))))

(add-hook 'org-after-todo-state-change-hook #'glz/org-auto-clock)

(defun glz/org-todo-menu ()
  "Set the TODO state of the entry at point (Org or agenda) from a popup menu.
Also offers Clock in / Clock out.  Meant for a tap (Android tool bar)."
  (interactive)
  (let* ((agenda (derived-mode-p 'org-agenda-mode))
         (marker (cond (agenda (or (org-get-at-bol 'org-hd-marker)
                                   (user-error "No entry on this line")))
                       ((derived-mode-p 'org-mode) nil)
                       (t (user-error "Not in an Org buffer"))))
         (states (if marker
                     (with-current-buffer (marker-buffer marker) org-todo-keywords-1)
                   org-todo-keywords-1))
         (choice (x-popup-menu
                  (if (listp last-nonmenu-event) last-nonmenu-event t)
                  (list "TODO state"
                        (cons "" (append (mapcar (lambda (s) (cons s s)) states)
                                         '(("(no state)" . none) "--"
                                           ("Clock in" . clock-in) ("Clock out" . clock-out))))))))
    (pcase choice
      ('nil nil)
      ('clock-in (if agenda (org-agenda-clock-in) (org-clock-in)))
      ('clock-out (if agenda (org-agenda-clock-out) (org-clock-out)))
      (_ (if agenda (org-agenda-todo choice) (org-todo choice))))))

**** AUCTeX-based LaTeX preview (org-auctex)
Org's built-in LaTeX preview (=dvipng=, synchronous) recompiles the whole
LaTeX preamble on every preview, which is the main source of slowness on
notes with many equations. AUCTeX's =preview-latex= can avoid that by
caching a precompiled preamble format dump (=preview-auto-cache-preamble=),
so only the fast body pass reruns — but that dump step shells out to
=pdflatex -ini= expecting a =mylatex.ltx= file that this system's TeX Live
package doesn't ship, so the dump always fails; worse, the failed dump
leaves AUCTeX's internal state inconsistent and causes *every* following
preview to mis-detect PDF output as DVI and invoke =dvips= on a
nonexistent =.dvi=, erroring with "End of Preview snippet 1 unexpected".
Preamble caching is left off until a =mylatex.ltx= is provisioned.
=org-auctex= wires the AUCTeX preview engine into Org, replacing the
=org-latex-preview= binding (=C-c C-x C-l=) with its own async-friendly
version while the minor mode is on.

Previews render as SVG (via =dvisvgm=) rather than PNG, so they scale
losslessly with =text-scale-adjust= / buffer zoom instead of going
blurry — =preview-dvisvgm-command= bakes the buffer's current
=text-scale-mode= zoom directly into dvisvgm's =--scale=@ argument, so
zooming the buffer and re-previewing keeps equations sized to match
the surrounding text. dvisvgm's SVG backend only ever runs on a genuine
=.dvi= file, though: AUCTeX's dispatcher silently falls back to its
Ghostscript/PNG pipeline whenever the preview compile produced a PDF
instead (detected via the =Preview: PDFoutput= marker in the log), with
no error — so =TeX-PDF-mode= is turned off buffer-locally in org
buffers below, forcing plain =latex= (DVI output) for these preview
compiles specifically, without touching =TeX-PDF-mode='s global default
of =t= that a real standalone =.tex= file would still get.

AUCTeX separately sizes *raster* preview images (PNG/JPEG/etc., the
fallback path above and the default for everything before this SVG
switch) from the monitor's reported physical size
(=frame-monitor-attributes='s =mm-size=), dividing pixel geometry by it
to get a DPI. On this laptop's panel, XRandR reports that physical size
with width and height swapped — =118x189mm= for a =2560x1600=
*landscape* panel, i.e. portrait-shaped mm for landscape pixels — which
makes the horizontal and vertical DPI differ by a factor of ~2.5
instead of matching, so a raster preview comes out stretched or
squashed on one axis (sometimes squashed badly enough to look blank).
The advice below detects exactly that landscape-pixels/portrait-mm
mismatch and swaps the mm dimensions back before AUCTeX divides by
them. It's a no-op for any monitor reporting sane geometry, and with
SVG previews it mostly guards the fallback path, since SVG is
resolution-independent and never consults this DPI.

AUCTeX native-compiles ~380 elisp files on install and needs a real TeX
toolchain (=latex=, =dvisvgm=) on =PATH= — neither is realistic on a phone
build of Emacs, so this is skipped on Android like the other native-compile
/ external-toolchain modules (see Feature Flags).
#+begin_src emacs-lisp
(when glz/enable-latex-preview
  (use-package auctex
    :defer t
    :custom
    ;; Precompiled-preamble caching needs a `mylatex.ltx' this TeX Live
    ;; install doesn't provide; when it fails it corrupts every later
    ;; preview's PDF/DVI detection, so leave it off (see prose above).
    (preview-auto-cache-preamble nil)
    ;; Fallback raster type if a preview ever compiles to PDF anyway
    ;; (see `TeX-PDF-mode' below); SVG previews don't use this at all.
    (preview-image-type 'dvi*)
    (preview-dvi*-image-type 'svg)
    (preview-dvi*-command #'preview-dvisvgm-command)
    ;; Every compile (.aux/.log/.dvi, one set per preview) otherwise lands
    ;; right next to the .org/.tex file being edited. A relative path here
    ;; is resolved under TeX-master's own directory and treated as
    ;; pre-approved (no "is this safe" prompt) since it's a subdirectory of
    ;; it — collects the clutter into one hidden folder per notes
    ;; directory instead of scattering loose files. preview-mode's own
    ;; per-session image temp dirs (the basename.prv/ directories) already
    ;; self-organize this way regardless.
    (TeX-output-dir ".auctex-build"))


  (use-package org-auctex
    :vc (:url "https://github.com/karthink/org-auctex" :rev :newest)
    :after org
    ;; org-mode loads early at startup regardless, so requiring auctex
    ;; here (rather than gating on an `auctex' feature nothing else ever
    ;; loads) is what actually makes `org-auctex-mode' turn on in org
    ;; buffers instead of silently never firing. `auctex' alone only
    ;; loads the autoloads shim (`tex-site'), not the real `tex.el' that
    ;; defines `TeX-PDF-mode' and the rest, so both are required here.
    :init (require 'auctex) (require 'tex)
    :hook ((org-mode . org-auctex-mode)
           ;; SVG previews need a real .dvi, which only a plain `latex'
           ;; (not `pdflatex') compile produces; scoped to org buffers
           ;; so a real standalone .tex file still gets pdflatex.
           (org-mode . (lambda () (TeX-PDF-mode -1)))))

  (with-eval-after-load 'preview
    (advice-add
     'preview-get-dpi :around
     (lambda (orig-fn)
       (let* ((attrs (frame-monitor-attributes))
              (mm (cdr (assq 'mm-size attrs)))
              (geom (nthcdr 3 (assq 'geometry attrs)))
              (pixel-w (nth 0 geom)) (pixel-h (nth 1 geom))
              (mm-w (nth 0 mm)) (mm-h (nth 1 mm)))
         (if (and (integerp mm-w) (integerp mm-h) (> mm-w 0) (> mm-h 0)
                  (> pixel-w pixel-h) (< mm-w mm-h))
             (cons (/ (* 25.4 pixel-w) mm-h) (/ (* 25.4 pixel-h) mm-w))
           (funcall orig-fn)))))))
#+end_src

;; Preview SVGs are rendered once, with the text scale at that moment baked
;; into dvisvgm's --scale, so zooming afterwards leaves them at the old size.
;; Re-render the existing previews (debounced) whenever the zoom changes.
(when glz/enable-latex-preview
  (defvar-local glz/latex-rescale-timer nil)

  (defun glz/org-latex-rescale ()
    "Regenerate this buffer's LaTeX previews at the current text scale."
    (setq glz/latex-rescale-timer nil)
    (when (and (derived-mode-p 'org-mode)
               (seq-some (lambda (o) (overlay-get o 'preview-state))
                         (overlays-in (point-min) (point-max))))
      (org-auctex-preview-clearout-buffer)
      (org-auctex-preview-buffer)))

            (run-with-idle-timer 0.6 nil

                                   (lambda ()
                                     (when (buffer-live-p buf)
                                       (with-current-buffer buf
                                         (glz/org-latex-rescale)))))))))

*** Emacs client popup frames
Emacs runs as a daemon started at login (=runemacs --daemon=); Windows
shortcuts call =emacsclientw= to open frames.  A frame opened with
=-F "((glz-popup . t))"= is a single-purpose popup: its buffers fill the
whole frame, and the frame closes when the task is done.  Shortcuts call
the real commands directly, e.g.:

#+begin_example
emacsclientw -n -u -c -F "((glz-popup . t) (width . 100) (height . 25))" -e "(run-at-time 0 nil #'org-capture)"
#+end_example

=run-at-time= lets the client return immediately; otherwise a prompt
(like the capture template menu) would block the server until answered.
To make another workflow close its popup, add =glz/popup-frame-close= to
that workflow's "done" hook.  The main-window shortcut calls
=glz/focus-main-frame= so it never lands in a leftover popup.
#+begin_src emacs-lisp

             '((lambda (_buffer _action) (frame-parameter nil 'glz-popup))
               (display-buffer-full-frame)))

  (when (frame-parameter nil 'glz-popup)
    (delete-frame)))

  "Return the main graphical Emacs frame, ignoring popup frames."

*** Dashboard (start page)
A Doom-style start page in about a hundred lines and no package: a banner
(GLZ in slanted letters with speed lines, "GLZ OS · personal operating
system" underneath),
today's date and planned training, and a short menu of the things done most
often.  It is the first buffer at startup and in every new =emacsclient -c=
frame (popup frames run a command and are not affected), and comes back with
=SPC d= or the home button of the Android tool bar.

Building it loads nothing: org, sprint.el and consult are only loaded when
an entry is used.  The "Today" line needs sprint.el; until org has been
loaded it says so, unless =glz/dashboard-preload-sprint= is set (Android
only, by default): then org and sprint.el are loaded one second after
startup, once Emacs is idle, and the line fills in by itself.

Every entry can be pressed with its key, with =RET=, or tapped.  The same
keys work only in the dashboard; the right column shows the leader key that
reaches the command from anywhere (hidden on narrow screens).

| Key | Entry                | Key | Entry                           |
|-----+----------------------+-----+---------------------------------|
| t   | today's training     | a   | agenda dashboard                |
| l   | log the session      | T   | Tasks.org                       |
| d   | not as planned today | N   | find a note (org-roam or Notes) |
| S   | sprint agenda        | r   | recent files                    |

(defun glz/keymap-menu (prompt keymap)
  "Choose a command of KEYMAP in the minibuffer, by key and which-key label."
  (let (cands)
    (map-keymap
     (lambda (event def)
       ;; which-key labels are stored in the keymap as (LABEL . COMMAND).
       (let* ((label (and (consp def) (stringp (car def)) (car def)))
              (cmd (if label (cdr def) def)))
         (when (commandp cmd)
           (push (cons (format "%-2s %s" (single-key-description event)
                               (or label (if (symbolp cmd) cmd "command")))
                       cmd)
                 cands))))
     keymap)
    (let ((choice (completing-read
                   prompt
                   (lambda (str pred action)
                     (if (eq action 'metadata)
                         '(metadata (display-sort-function . identity))
                       (complete-with-action action cands str pred)))
                   nil t)))
      (call-interactively (cdr (assoc choice cands))))))

(defvar-local glz/dashboard--width nil "Window width the dashboard was drawn for.")

(defun glz/dashboard-render ()
  "Draw the dashboard in the current buffer for its window's width."
  (let* ((win (get-buffer-window (current-buffer) t))
         (width (if win (window-body-width win) (frame-width)))
         (wide (>= width 52))
         (item-width (if wide 44 30))
         (pad (make-string (max 0 (/ (- width item-width) 2)) ?\s))
         (center (lambda (str face)
                   (insert (make-string (max 0 (/ (- width (string-width str)) 2)) ?\s)
                           (propertize str 'face face) "\n")))
         (inhibit-read-only t))
    (setq glz/dashboard--width width)
    (erase-buffer)
    (insert "\n")
    (let* ((fits (lambda (art) (<= (apply #'max (mapcar #'string-width art)) width)))
           (art (if (funcall fits glz/dashboard-banner) glz/dashboard-banner
                  glz/dashboard-banner-narrow))
           (left (make-string (max 0 (/ (- width (apply #'max (mapcar #'string-width art))) 2)) ?\s)))
      (dolist (line art)
        (insert left (propertize line 'face 'glz/dashboard-banner) "\n")))
    (funcall center (truncate-string-to-width glz/dashboard-tagline width nil nil "…")
             'glz/dashboard-hint)
    (insert "\n")
    (funcall center (format-time-string "%A %e %B %Y") 'glz/dashboard-heading)
    (dolist (line (glz/dashboard--sprint-lines))
      (funcall center (truncate-string-to-width line (max 10 (- width 2)) nil nil "…")
               'glz/dashboard-hint))
    (dolist (section glz/dashboard-sections)
      (insert "\n" pad (propertize (car section) 'face 'glz/dashboard-heading) "\n")
      (pcase-dolist (`(,key ,label ,cmd ,hint) (cdr section))
        (let ((right (if (and wide hint) hint "")))
          (insert
           (propertize
            (concat pad
                    (propertize key 'face 'glz/dashboard-key) "  "
                    label
                    (make-string (max 1 (- item-width 3 (string-width label) (string-width right))) ?\s)
                    (propertize right 'face 'glz/dashboard-hint))
            'glz-cmd cmd 'mouse-face 'highlight 'keymap glz/dashboard-item-map
            'help-echo (format "%s (%s)" label cmd))
           "\n"))))
    (insert "\n")
    (funcall center (format "%d packages · loaded in %s" (length package-activated-list)
                            (emacs-init-time "%.2fs"))
             'glz/dashboard-hint)
    (goto-char (point-min))
    (glz/dashboard-next 1)))

*** Shortcuts from outside Emacs (Android home screen)
Any of the dashboard workflows can be opened directly from the phone's home
screen, like a separate app.  The mechanism is =org-protocol=: Emacs for
Android registers itself as the handler of =org-protocol://= links (see the
"Android File System" node of the Emacs manual), and a link

#+begin_example
org-protocol://glz?go=note
#+end_example

runs the command named =note= in =glz/shortcuts= (only those commands: a
link from a web page cannot run anything else).  The same links work on the
desktop daemon, e.g. =emacsclient -n "org-protocol://glz?go=note"= for a
NixOS key binding.

| go=       | Opens         | go=    | Opens            |
|-----------+---------------+--------+------------------|
| home      | dashboard     | today  | today's training |
| note      | new note      | log    | log the session  |
| checklist | new checklist | task   | new task         |
| notes     | notes board   | agenda | agenda dashboard |
| capture   | capture menu  | weight | weigh-in         |

*Setting it up on the phone, with Termux:Widget* (one icon per workflow):
1. Install Termux:Widget from F-Droid.  It must be signed with the same key
   as Termux, so re-sign it the way Termux and Emacs were re-signed for the
   shared user ID (Pre-Early-Init → Termux binaries on PATH).
2. In Emacs: =M-x glz/android-install-shortcuts=.  It writes one small script
   per entry of =glz/shortcuts= into =~/.shortcuts/tasks/= of Termux (tasks
   run in the background, without opening a terminal).  Each script just
   sends the link: =am start -a android.intent.action.VIEW -d 'org-protocol://glz?go=note'=.
3. On the home screen: long-press → Widgets → Termux:Widget.  The 1×1
   "shortcut" widget puts a single entry (e.g. /New note/) on the home
   screen as its own icon; the list widget shows all of them.  The first time,
   Android may ask which app opens the link: choose Emacs, "Always".

*Without Termux:Widget*, any launcher or app that makes home-screen
shortcuts for an intent or URL (an "intent shortcut", e.g. Shortcut Maker)
works: action =android.intent.action.VIEW=, data =org-protocol://glz?go=…=.

Emacs needs its server running to receive the link: it is started on
Android at startup.  If Emacs is not running at all, Android starts it with
the link as argument; that is handled too, once startup has finished.
#+begin_src emacs-lisp
(defconst glz/shortcuts
  '(("home"      "Emacs"            glz/dashboard)
    ("note"      "New note"         glz/capture-note)
    ("checklist" "New checklist"    glz/capture-checklist)
    ("notes"     "Notes"            glz/notes-board)
    ("task"      "New task"         glz/capture-task)
    ("capture"   "Capture"          org-capture)
    ("agenda"    "Agenda"           glz/agenda-dashboard)
    ("today"     "Today's training" glz/sprint-today)
    ("log"       "Log training"     glz/sprint-log)
    ("weight"    "Weigh-in"         glz/capture-weight))
  "Commands reachable as org-protocol://glz?go=NAME: (NAME LABEL COMMAND).
LABEL names the Termux:Widget script.")

(defun glz/org-protocol-go (info)
  "Run the `glz/shortcuts' command named by the go= parameter of INFO."
  (let* ((name (plist-get info :go))
         (cmd (nth 2 (assoc name glz/shortcuts))))
    (if (not cmd)
        (message "org-protocol glz: unknown shortcut %S" name)
      ;; Leave the server process first: captures read keys and prompts.
      (run-at-time 0 nil (lambda () (call-interactively cmd)))))
  nil)

(with-eval-after-load 'org-protocol
  (add-to-list 'org-protocol-protocol-alist
               '("glz" :protocol "glz" :function glz/org-protocol-go)))

;; The desktop daemon has no startup screen to slow down: have the links

  ;; recognised once org-protocol is loaded (it loads org: done when idle).
  (add-hook 'emacs-startup-hook
            (lambda ()
              (require 'server)
              (unless (server-running-p) (server-start))
              (run-with-idle-timer 1.5 nil (lambda () (require 'org-protocol)))))

  ;; Emacs was not running: the link is a command-line argument.
  (add-hook 'command-line-functions
            (lambda ()
              (when (string-prefix-p "org-protocol:" (symbol-value 'argi))

                            (lambda ()
                              (require 'org-protocol)
                              (org-protocol-check-filename-for-protocol url nil nil))
                            90))
                t)))

    "Write a Termux:Widget script for every entry of `glz/shortcuts'."

                    (format "am start -a android.intent.action.VIEW -d 'org-protocol://glz?go=%s' >/dev/null 2>&1\n"

          (set-file-modes file #o700)))
      (message "%d shortcuts written to %s; add them with the Termux:Widget widget"
               (length glz/shortcuts) dir))))

*** Icon fonts on Android
The mode line (doom-modeline → nerd-icons) and Dired (all-the-icons-dired)
draw icons with special fonts; without them a phone shows random
characters.  Their own installers do not work on Android: they know only the
Linux and macOS font folders, then run =fc-cache=, which does not exist
there.  Emacs on Android reads fonts from the system and from the =fonts=
folder in its own home (=~/fonts=, i.e. =/data/data/org.gnu.emacs/files/fonts=),
and only at startup (see the "Android Fonts" node of the Emacs manual).

So on Android =M-x nerd-icons-install-fonts= and =M-x all-the-icons-install-fonts=
both download every icon font into =~/fonts=; then restart Emacs.  Until the
fonts are there, the phone draws no icons rather than wrong ones.

If the download fails (no TLS in the Emacs build and no Termux =gnutls-cli=),
fetch the font from Termux instead, which can write into Emacs's folder thanks
to the shared user ID:
#+begin_example
mkdir -p /data/data/org.gnu.emacs/files/fonts && cd $_
curl -LO https://raw.githubusercontent.com/rainstormstudio/nerd-icons.el/main/fonts/NFM.ttf
#+end_example

*** Ediff settings
Ediff uses =run-hooks= instead of =run-mode-hooks= in its control buffer, so
=meow-global-mode= never sees it.  We manually enable meow in motion state
there so the SPC leader still works.  Ediff's own single-key commands (n/p/a/b/q)
fall through because they are not bound in =meow-motion-map=.  Diff buffers are
also put in motion state during the session and restored to normal on quit.
This whole block only makes sense as part of a git/magit-centric diff
workflow, so it is skipped wherever magit is (see =glz/enable-magit=).
#+begin_src emacs-lisp
(when glz/enable-magit
(use-package ediff
  :ensure nil
  :defer t
  :config
  (setq ediff-keep-variants nil)
  (setq ediff-make-buffers-readonly-at-startup nil)
  (setq ediff-merge-revisions-with-ancestor t)
  (setq ediff-show-clashes-only t)
  (setq ediff-split-window-function 'split-window-horizontally)
  ;; On Windows, prefer the Git-bundled diff/diff3 as an explicit fallback.
  (when (eq glz/platform 'windows)
    (let ((diff  (or (executable-find "diff")
                     "C:/Program Files/Git/usr/bin/diff.exe"))
          (diff3 (or (executable-find "diff3")
                     "C:/Program Files/Git/usr/bin/diff3.exe")))
      (setq ediff-diff-program  diff
            ediff-diff3-program diff3)))

  ;; Put the ediff control buffer in motion state so SPC leader works
  ;; while ediff's single-key commands still fall through.
  (add-hook 'ediff-mode-hook
            (lambda ()
              (meow-mode 1)
              (meow--switch-state 'motion)))

  ;; Track whether an ediff session is active so the auto-restore hook
  ;; (below) does not undo ediff's deliberate motion-state setup.
  (defvar glz/ediff-in-progress nil
    "Non-nil while an ediff session is active.")

  (defun glz/meow-suspend-for-ediff ()
    "Switch diff buffers to motion state so ediff keys pass through."
    (dolist (buf (list ediff-buffer-A ediff-buffer-B ediff-buffer-C
                       ediff-ancestor-buffer))
      (when (buffer-live-p buf)
        (with-current-buffer buf
          (meow--switch-state 'motion)
          ;; meow-setup-line-number sets type to t in motion state;
          ;; override it so relative numbers are preserved during ediff.
          (setq-local display-line-numbers-type 'relative)))))

  (defun glz/meow-restore-after-ediff ()
    "Restore normal state in diff buffers after ediff exits."
    (setq glz/ediff-in-progress nil)
    (dolist (buf (list ediff-buffer-A ediff-buffer-B ediff-buffer-C
                       ediff-ancestor-buffer))
      (when (buffer-live-p buf)
        (with-current-buffer buf (meow--switch-state 'normal))))
    ;; ediff restores the window configuration after this hook returns,
    ;; so the buffer the user lands in may not be in the list above.
    ;; Defer a final normal-state switch until ediff fully exits.
    (run-with-idle-timer 0 nil
                         (lambda ()
                           (when (bound-and-true-p meow-mode)
                             (meow--switch-state 'normal)))))

  ;; Auto-restore normal state when selecting any regular file buffer
  ;; that ended up in motion state (e.g. after ediff or magit navigation).
  (defun glz/meow-normal-on-file-select (&optional _frame)
    "Switch to normal meow state when a writable file buffer is selected.
Skipped while ediff is active so the motion-state setup there is
not immediately undone."
    (when (and (not glz/ediff-in-progress)
               (bound-and-true-p meow-mode)

*** Perspective (project-scoped workspaces)
Each project gets its own perspective: a named workspace with its own
buffer list and window layout, all inside the same frame.  Non-project
work lives in the =main= perspective.

=project-switch-project= (=C-x p p= and =SPC w p=) is advised so that
picking a project switches to its perspective.  A new perspective shows
the usual =project-switch-commands= menu; an existing one is restored
exactly as you left it.  =consult-buffer= only lists the current
perspective's buffers by default; the hidden "all buffers" source is
still reachable via consult's narrowing keys.

| Key       | Action                                 |
|-----------+----------------------------------------|
| =SPC w p= | open/switch to a project's perspective |
| =SPC w P= | switch to any perspective by name      |
| =SPC w n= | next perspective                       |
| =SPC w N= | previous perspective                   |
| =SPC w X= | kill perspective (and its own buffers) |
| =C-c M-p= | full =persp-mode= prefix map           |

  (glz/load-local "testfall-mode.el")

  (defun glz/testfall-buffer-p ()
    "Return non-nil if the buffer content matches testfall grammar patterns."
    (save-excursion
      (save-restriction
        (widen)
        (goto-char (point-min))
        ;; Match patterns that are highly distinctive to testfall files
        (re-search-forward
         (rx (or "<Konzern-Varianten>"
                 (seq "DUT::" (+ (any alpha "_")))
                 (seq "VAR::" (+ (any alpha "_")))
                 (seq "CAL::" (+ (any alpha "_")))
                 (seq bol "Variation:")
                 (seq bol "VarEnd")))
         (min (point-max) 100000)
         t))))

    "Apply testfall-base-mode to the current buffer if it contains testfall content.
Forces full refontification: font-lock-flush clears any stale 'fontified'
text properties that jit-lock would otherwise skip, then font-lock-ensure
drives immediate fontification regardless of display state."
    (when (and (not (derived-mode-p 'testfall-base-mode))
               (glz/testfall-buffer-p))
      (testfall-base-mode)
      ;; jit-lock marks already-fontified regions with text property
      ;; 'fontified=t and skips them.  After a mode change the previous
      ;; mode's fontification is still on the text; flush it so that
      ;; jit-lock-fontify-now (called by font-lock-ensure) re-applies
      ;; the new testfall keyword rules over the whole buffer.
      (font-lock-flush)
      (font-lock-ensure)))

    (when (and (not (bound-and-true-p glz/ediff-in-progress))
               buffer-file-name
               (not (string-match-p "\\.org\\'" buffer-file-name)))
      (glz/testfall-apply)))

  (add-hook 'hack-local-variables-hook #'glz/maybe-enable-testfall-mode)

*** Open binary files with OS default application
Files whose extension matches =glz/external-file-extensions= are handed off
to the OS default application (Explorer/xdg-open) and the Emacs buffer is
immediately discarded.  Extend the list to taste — or shrink it to remove
types you prefer to handle inside Emacs (e.g. =pdf= if you use =pdf-tools=).

#+begin_src emacs-lisp
(when glz/enable-open-externally

  (defvar glz/external-file-extensions
    '(;; Microsoft Office
      "xlsx" "xls" "xlsm" "xlsb"
      "docx" "doc" "docm"
      "pptx" "ppt" "pptm"
      ;; OpenDocument
      "odt" "ods" "odp" "odg"
      ;; Images
      "png" "jpg" "jpeg" "gif" "bmp" "tiff" "tif" "webp" "svg" "ico"
      ;; Audio / Video
      "mp3" "wav" "flac" "ogg" "aac"
      "mp4" "avi" "mkv" "mov" "wmv" "webm"
      ;; Archives
      "zip" "rar" "7z" "tar" "gz" "bz2" "xz"
      ;; Misc binary
      "exe" "msi" "dmg" "iso")
    "Extensions delegated to the OS default application instead of Emacs.")

  (defun glz/open-file-with-os-default (file)
    "Open FILE using the OS default application."
    (pcase glz/platform
      ('windows (w32-shell-execute "open" (expand-file-name file)))
      (_        (call-process "xdg-open" nil 0 nil (expand-file-name file)))))

  (defun glz/maybe-open-externally ()
    "Hand off the visited file to the OS when its extension is external."
    (when-let* ((file buffer-file-name)
                (ext  (file-name-extension file))
                (_    (member (downcase ext) glz/external-file-extensions)))
      (glz/open-file-with-os-default file)
      (let ((buf (current-buffer)))
        (run-with-idle-timer 0 nil #'kill-buffer buf))))

  (add-hook 'find-file-hook #'glz/maybe-open-externally))
#+end_src

*** C / LSP (eglot + clangd)
Requires =clangd= on =PATH= (part of LLVM/Clang).  On Windows install via
=winget install LLVM.LLVM= or the LLVM installer; on Linux install the
=clangd= package.  A =compile_commands.json= (generated by CMake with
=-DCMAKE_EXPORT_COMPILE_COMMANDS=ON= or by Bear) in the project root gives
clangd full cross-file awareness.  Skipped on Android — no realistic C/C++
dev workflow there, and clangd wouldn't be on =PATH= anyway.
#+begin_src emacs-lisp
(when glz/enable-lsp-c
  ;; ----- Eglot: clangd for C/C++ -----
  (use-package eglot
    :ensure nil
    :preface
    (defun glz/eglot-c-maybe-start ()
      "Start eglot for C/C++ only when clangd is available."
      (when (executable-find "clangd")
        (eglot-ensure)))
    :config
    (add-to-list 'eglot-server-programs
                 '((c-mode c++-mode c-ts-mode c++-ts-mode)
                   . ("clangd"
                      "--background-index"
                      "--clang-tidy"
                      "--header-insertion=never"
                      "--completion-style=detailed"
                      "--function-arg-placeholders=0")))
    :hook ((c-mode c++-mode c-ts-mode c++-ts-mode) . glz/eglot-c-maybe-start)))
#+end_src
